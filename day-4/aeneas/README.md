# Afternoon session — Aeneas

The tool **Aeneas** translates a Rust program into Lean definitions, so that
properties of the program can be stated and proved in Lean. The translation has
two steps. The tool **Charon** translates a Rust crate into LLBC, the Low-Level
Borrow Calculus, an intermediate representation stored in a `.llbc` file.
Aeneas then translates the LLBC file into a Lean file with a definition for
each Rust function; a function that contains a loop gives several definitions,
one for the loop body, one for the loop and one for the function itself. The
generated definitions are pure functions: they have no mutable state, and a
Rust function that modifies its argument becomes a Lean function that returns
the modified value.

A Rust program can **panic**, that is, stop with an error, for example when an
index is outside an array, or when an addition overflows in a program compiled
in debug mode. The translation treats an overflow of `+`, `-` or `*` as a
failure in both debug and release mode. The generated functions therefore return
a value of the type `Result α`, whose constructors are `ok v` for a normal
result `v`, `fail e` for a panic with the error `e`, and `div` for a computation
that does not terminate.

The folder [`rust_workspace/`](rust_workspace/README.md) contains the Rust
crates and the instructions for running Charon and Aeneas. The folder
[`lean_proofs/`](lean_proofs/README.md) is a Lake project. Each file in its
folder `Proofs/` consists of the definitions generated by Aeneas for one crate,
followed by specifications and proofs.

## Three forms of a specification

A specification of a function `f` describes the result of `f x`. The files use
three ways of writing it: file `01` introduces the triple form and the
hypothesis form, and files `02` and `05` use the existential form.

| Form | Statement | Meaning |
| :--- | :--- | :--- |
| triple | `f x ⦃ r => P r ⦄` | `f x` is `ok r` for some `r` with `P r` |
| existential | `∃ r, f x = ok r ∧ P r` | the same; the two are equivalent by `WP.spec_equiv_exists` |
| hypothesis | `f x = ok r → P r` | if `f x` is `ok r`, then `P r`; nothing is stated when `f x` fails |

The first two forms state that the function neither panics nor runs forever:
the result is `ok`, not `fail` and not `div`. The third form states nothing
about failure.

## Building

From the folder `day-4/aeneas/lean_proofs/`, `lake exe cache get` downloads the
compiled Mathlib, and `lake build` compiles the Aeneas library and all files in
`Proofs/`. The Rust crates are needed only to regenerate the definitions; the
steps are in [`rust_workspace/README.md`](rust_workspace/README.md).
